# CAPTAIN local OCR provenance and scope

The browser extension bundles these exact free/offline npm distributions, copied
locally after installation with lifecycle scripts disabled:

- `tesseract.js@6.0.1` (Apache-2.0): browser API in `vendor/tesseract.min.js`,
  nested worker in `vendor/worker.min.js`. Source:
  https://github.com/naptha/tesseract.js ; npm distribution SHA-512:
  `/sPvMvrCtgxnNRCjbTYbr7BRu0yfWDsMZQ2a/T5aN/L1t8wUQN6tTWv6p6FwzpoEBA0jrN2UD2SX4QQFRdoDbA==`.
- `tesseract.js-core@6.0.0` (Apache-2.0): LSTM and SIMD-LSTM JS/WASM
  in `vendor/`. Source: https://github.com/naptha/tesseract.js-core ;
  npm SHA-512:
  `1Qncm/9oKM7xgrQXZXNB+NRh19qiXGhxlrR8EwFbK5SaUbPZnS5OMtP/ghtqfd23hsr1ZvZbZjeuAGcMxd/ooA==`.
- `@tesseract.js-data/eng@1.0.0` (npm package declares MIT):
  `4.0.0_best_int/eng.traineddata.gz` copied as
  `lang/eng.traineddata.gz`. Source:
  https://github.com/naptha/tessdata/tree/gh-pages/4.0.0_best_int .
  It is an integerized LSTM-only model derived from upstream tessdata_best;
  upstream tessdata trained assets declare Apache-2.0. Exact binary SHA-256:
  `45b4cb346724ac1774f1c36f42f182b887bcdb28ebe63e6fff90ac41f3fcff91`.

The complete applicable Apache-2.0 license is in both
`vendor/TESSERACTJS-LICENSE.txt` and
`vendor/TESSERACTCORE-LICENSE.txt`. Distribution-specific third-party
notices are alongside both minified scripts. The language npm distribution
declares MIT but contains no standalone LICENSE file; the MIT terms are
reproduced in `LANGUAGE-DATA-MIT-LICENSE.txt`.

Build packaging verifies byte lengths and SHA-256 of **all seven binary/JS
OCR assets**, and checks local loader and license presence before ZIP creation.
The browser loader independently hashes those same exact bytes before
recognition, sets extension-local worker/core/lang URLs, disables CDN/blob
workers and persistent language cache, and blocks nonlocal worker fetch,
XHR and importScripts. Only English/Latin input is supported by the installed
model; uncertain text or runtime failure must withhold the screenshot or
opaquely mask its uncertain region. Successful initialization proves only
that the engine loaded; its recognition completeness, real-browser behavior
and recall require separate measured validation.
